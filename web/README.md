# web

The JS half of the project, eventually served via GitHub Pages. A pnpm
workspace with these packages:

- `nn/` — a from-scratch, dependency-free, inference-only TS port of
  `llm/`'s `nn.py`: `TransformerLM` and its submodules (RoPE, multi-head
  attention, transformer blocks, RMSNorm, SwiGLU, embeddings), built on a
  minimal custom ndarray (no autograd — weights are trained in Python and
  imported). Every module records the tensors from its last forward pass
  (inputs/outputs, per-head attention weights, ...) via `getState()`, for
  `visualizer/`'s per-layer displays. `loadWeights()` reads the exact key
  names PyTorch's `model.state_dict()` produces, so a Python export step
  can hand its state dict to the JS side with no name translation —
  verified by `nn/tests/parity.test.ts`, which checks the JS forward pass
  against a fixture generated by the real Python model.
- `visualizer/` — loads the trained weights (from `weights/`) into `nn/`
  and runs them, wired up with visualizations of what's happening at each
  layer (activations, attention, etc.). Includes a "time" slider to slow
  inference down to a human-readable pace. Not yet implemented.
- `playground/` — the "module playground": a standalone, graphical
  explainer for how each module works (RoPE, attention, BPE, ...),
  independent of running the full model. Not yet implemented.
- `weights/` — exported weights from `llm/` training runs, served to the
  visualizer at runtime. Not yet implemented (no export step from the
  Python side yet).

## Usage

```sh
pnpm install         # from web/, installs all workspace packages
pnpm --filter @spiderman/nn test        # run the nn package's test suite
pnpm --filter @spiderman/nn typecheck
```
