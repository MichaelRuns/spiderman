# web

The JS half of the project, served via GitHub Pages (`.github/workflows/deploy-pages.yml`
builds and deploys on every push to `main`). A pnpm workspace with these packages:

- `nn/` — a from-scratch, dependency-free, inference-only TS port of
  `llm/`'s `nn.py`: `TransformerLM` and its submodules (RoPE, multi-head
  attention, transformer blocks, RMSNorm, SwiGLU, embeddings), built on a
  minimal custom ndarray (no autograd — weights are trained in Python and
  imported), plus a real per-layer **KV cache** for incremental decoding
  (`KVCache`, threaded through every module's `forward()`), a JS port of the
  BPE tokenizer's encode/decode (`Tokenizer`), and sampling
  (`sampleToken`: temperature/top-k/top-p). Every module records the
  tensors from its last forward pass (inputs/outputs, per-head attention
  weights, ...) via `getState()`/`cloneState()`, for `visualizer/`'s
  per-layer displays. `loadWeights()` reads the exact key names PyTorch's
  `model.state_dict()` produces, so a Python export step can hand its state
  dict to the JS side with no name translation — verified by
  `nn/tests/parity.test.ts` (full-sequence forward) and
  `nn/tests/kvcache.test.ts` (bit-exact parity between step-by-step cached
  decoding and full-sequence recompute), both checked against a fixture
  generated by the real Python model.
- `visualizer/` — a React + Vite app, no separate "output" area: one box
  for typing and generated output alike, live-tokenized as you type (every
  token colored by a deterministic hash of its vocabulary id, so the same
  token always looks the same wherever it recurs) and appended to directly
  as the model generates. Clicking any generated token pins the rest of the
  UI — the ranked next-token probabilities (real softmax over that step's
  logits, sampled token highlighted) and the architecture diagram — to that
  step's actual captured state; otherwise both follow the newest token
  live. The diagram is a classic layer-by-layer box-and-arrow figure (input
  embedding → per-layer RMSNorm/masked-attention/residual/RMSNorm/SwiGLU ×
  N → final norm → linear → softmax), reflecting this model's real
  pre-norm/RoPE/SwiGLU architecture rather than a generic template, each
  box showing that layer's real activation/attention/KV-cache data for a
  layer you pick via tabs. It's rendered on a plain 2D canvas (no WebGL) —
  cheap enough to redraw on every token — that resizes itself to fit any
  viewport down to phone width. A "min ms/token" control paces how fast
  tokens visibly appear (real compute is often single-digit ms — too fast
  to watch) without touching the separately-reported real perf stats
  (current/min/avg time per token, tokens/sec, KV cache size).
- `playground/` — the "module playground": a standalone, graphical
  explainer for how each module works (RoPE, attention, BPE, ...),
  independent of running the full model. Not yet implemented.
- `weights/` — exported weights from `llm/` training runs
  (`llm/src/spiderman_llm/scripts/export_weights.py`): `weights.bin` (raw
  float32, ~8MB) + `manifest.json` + `vocab.json`/`merges.json`, served to
  the visualizer at runtime and tracked in git (small enough by design).

## Usage

```sh
pnpm install                                    # from web/, installs all workspace packages
pnpm --filter @spiderman/nn test                # nn package's test suite
pnpm --filter @spiderman/nn typecheck
pnpm --filter @spiderman/visualizer dev         # run the visualizer locally
pnpm --filter @spiderman/visualizer build       # production build (what CI deploys)
```

## Deploying

Pushing to `main` (with changes under `web/`) triggers
`.github/workflows/deploy-pages.yml`, which builds `visualizer/` and
publishes it to GitHub Pages. One-time manual step: repo Settings → Pages →
Source: **GitHub Actions**.
